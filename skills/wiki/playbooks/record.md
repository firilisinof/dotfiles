# Record

Start with the notes you used. Keep explicit preferences, decisions with reasons, personal knowledge, verified operational surprises, reusable fixes and requested references. Preserve rare personal outcomes even when they create no current task. Prefer editing an existing note. Search for other guidance affected by a change.

Keep information available from source code and its manuals there. Link to it when the private note contributes the reason, pitfall or recovery detail. Keep raw results in the project repository. Follow the vault README for attachments. Omit routine chat logs, secrets, inferred personal details and transcripts.

Distinguish accepted state from proposals. Keep current decisions in one place. Retire an adopted plan and transfer lasting decisions to the project. Keep superseded rationale briefly in history only when useful. Use the Things skill for actionable tasks. Create one with consent and mark it complete when its outcome exists.

Read [the note format](../references/note-format.md) before writing. Pull before editing. Keep unrelated work intact. Check changed links and run `wiki-check`. Stage only the intended paths, commit each logical update, and push. If a concurrent push wins, rebase and reconcile both sides. Report an unresolved failure. Never skip the pre-commit hook or force-push. Protected instruction changes require an explicit request and `WIKI_ALLOW_PROTECTED=1 git commit`. Only the coordinating agent writes to the wiki.
